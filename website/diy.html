🛠️ DIY Technical Setup

Build and customize everything yourself. Full control and deep learning.

For Developers & Technical Enthusiasts

This path is for you if you want complete control over your ECG monitoring system, enjoy building things from scratch, and want to learn about IoT, cloud architecture, and AI integration. You'll set up everything manually and can customize every aspect of the system.

What You'll Learn

🔌 IoT & Hardware

Raspberry Pi GPIO, SPI communication, ECG signal acquisition from ADS1293 chip

☁️ Cloud Architecture

AWS IoT Core, Lambda serverless, DynamoDB, S3, SQS, API Gateway

🤖 AI Integration

Claude API for medical analysis, prompt engineering for ECG interpretation

📊 Signal Processing

Digital filtering, noise reduction, QRS detection, HRV calculation

🏗️ Infrastructure as Code

Terraform for repeatable deployments, environment management

⚛️ Modern Frontend

Next.js 14, React 18, TypeScript, real-time data visualization

Prerequisites

Technical Skills Required

  • Intermediate to Advanced: Comfortable with command line, Git, and debugging
  • Languages: Python (for Raspberry Pi), TypeScript/JavaScript (for dashboards)
  • Cloud: AWS basics (IAM, CloudWatch, basic service understanding)
  • Infrastructure: Familiarity with Terraform or willingness to learn
  • Linux: Basic Linux administration for Raspberry Pi

Tools & Accounts

AWS Account

Active account with billing enabled. You'll need IAM permissions for IoT, Lambda, DynamoDB, S3, SQS, API Gateway, CloudWatch, Secrets Manager.

AWS CLI

Version 2.x, configured with credentials (aws configure)

Terraform

Version >= 1.5.0 for infrastructure deployment

Claude API Key

Sign up at console.anthropic.com

Python

Version 3.9+ for Pi collector/streamer

Your Journey (3-5 Hours)

  1. Clone Repository & Explore

    Clone the ECG_Monitor repo, read ARCHITECTURE.md and PROJECT_STRUCTURE.md to understand the system design. Review the technology choices in DESIGN_DECISIONS.md.

    git clone https://github.com/23blocks-OS/ECG_Monitor.git
cd ECG_Monitor
cat ARCHITECTURE.md
cat DESIGN_DECISIONS.md

  2. Configure Terraform Variables

    Navigate to terraform/environments/poc/, copy the example config, and edit with your AWS region, email for alerts, and Claude API key.

    cd terraform/environments/poc
cp terraform.tfvars.example terraform.tfvars
nano terraform.tfvars  # Edit your values

  3. Deploy AWS Infrastructure

    Use the deploy script to build Lambda packages, deploy Terraform infrastructure, and generate Pi configuration. This creates IoT Core, Lambda functions, DynamoDB tables, S3 buckets, and API Gateway.

    cd ../../..  # Back to project root
./deploy.sh

    This takes ~10-15 minutes. Save the Terraform outputs (IoT endpoint, API Gateway URL, etc.)

  4. Set Up Raspberry Pi Hardware

    Install Raspberry Pi OS, connect CJMCU-1293 via SPI (check docs/raspberry-pi-deployment.md for pinout), and enable SPI interface using raspi-config.

  5. Configure Pi Collector & Streamer

    Copy the generated config to your Pi, install Python dependencies, and set up AWS IoT certificates.

    scp config/pi-config-deployed.yaml pi@raspberrypi:~/

# On Raspberry Pi
ssh pi@raspberrypi
git clone https://github.com/23blocks-OS/ECG_Monitor.git
cd ECG_Monitor/pi-collector
pip3 install -r requirements.txt

cd ../pi-streamer
pip3 install -r requirements.txt

mkdir -p ~/certs
# Copy device.crt, device.key, AmazonRootCA1.pem from Terraform output

  6. Test Data Flow

    Start collector and streamer, verify data reaches AWS using CloudWatch Logs and DynamoDB Console.

    python3 pi-collector/main.py &
python3 pi-streamer/main.py &

# Check logs
tail -f /var/log/ecg-monitor.log

  7. Deploy Web Dashboards

    Build and deploy patient and provider portals to Vercel (or self-host on S3/CloudFront).

    # Patient Portal
cd dashboard-next
npm install
vercel deploy --prod

# Provider Portal
cd ../dashboard-org
npm install
vercel deploy --prod

  8. Create Organization & Users

    Use the Python scripts in scripts/create-organization.py to set up your organization, admin user, and initial patients in DynamoDB.

  9. Customize & Extend

    Now that everything works, customize the code! Adjust AI prompts in lambda/ai-analyzer/, modify dashboard UI, tune signal processing parameters, or integrate with your own systems.

What You Can Customize

Signal Processing

Adjust filtering parameters, sampling rates, QRS detection algorithms in pi-collector/signal_processor.py

AI Analysis

Modify Claude prompts for different analysis focus, add custom arrhythmia patterns, adjust confidence thresholds

Dashboard UI

Rebrand colors, add custom visualizations, create new chart types, modify layouts

Alert Logic

Change alert conditions, add SMS/Slack notifications, customize email templates

Data Storage

Adjust retention policies, add new fields to DynamoDB schema, implement archival strategies

Integrations

Connect to EMR/EHR systems, export to FHIR format, integrate with other health apps
